# DMAT Web 應用使用說明

適用對象:第一線醫護人員、站長、指揮官、系統管理者。
本說明對應核心垂直切片版本(紀錄單頁 1/8:拍攝 → AI 辨識 → 覆核 → 傷患主檔 → 儀表板)。

---

## 1. 啟動與登入

### 1.1 啟動服務

```powershell
cd "C:\Teemo\Cowork\急診DAMT 紙本計畫\dmat-system\src\Dmat.Web"
dotnet run
```

啟動後以瀏覽器開啟 **http://localhost:5100**(支援 Chrome / Edge / Safari,手機平板連同一區網 Wi-Fi 後以電腦 IP 開啟,如 `http://192.168.x.x:5100`)。

> 建議先啟動 AI 辨識服務(見《AI服務使用說明.md》)。AI 服務未啟動時系統仍可運作,
> 上傳的影像會自動降級為「人工輸入模式」,由覆核人員對照影像逐欄填寫。

### 1.2 登入帳號(開發/演練用)

| 帳號 | 角色 | 權限摘要 |
|---|---|---|
| `medic01`~`medic03` | 醫護人員 | 拍攝上傳、覆核、傷患資料、站內儀表板 |
| `leader01` | 站長 | 同醫護人員 |
| `commander` | 指揮官 | 儀表板態勢檢視 |
| `admin` | 系統管理者 | 全部功能 |

密碼一律為 `Dmat#2026`。連續輸入錯誤 5 次帳號將鎖定 15 分鐘。
**正式導入時必須更換全部帳號密碼。**

## 2. 醫護人員操作流程

### 2.1 拍攝/上傳紀錄單(選單「拍攝紀錄單」)

1. 點紅色大按鈕「📷 拍攝紀錄單」。手機(Android Chrome)會直接開啟相機;電腦則開啟檔案選擇視窗,可一次選多張。
2. 拍攝要領:紀錄單放平、避免反光與陰影、整頁入鏡、對焦清楚後再拍。
3. 影像會先進入畫面左下方的「上傳佇列」:
   - **連線正常**:自動上傳,幾秒後在右側「最近上傳結果」顯示「辨識完成,已進入覆核佇列」。
   - **離線/斷線**:影像保留在裝置佇列(顯示「待傳」),**不會遺失**;重新連上區網後自動補傳,約每 15 秒重試一次。
4. 常見結果訊息:
   - 「已上傳,辨識進行中」→ 正常。**上傳與辨識是分開的**:照片一送到就回應,
     辨識在伺服器背景排隊處理,所以可以連續拍、連續傳,不必等前一張辨識完。
   - 「影像重複(已併入既有紀錄)」→ 同一張影像已上傳過(SHA-256 比對),不會重複建檔。
   - 「上傳成功,但辨識未啟動」→ 訊息後方會附**具體原因**;影像已保留,
     排除問題後可在覆核頁按「↻ 重新辨識」重跑,不必重拍。

> 覆核佇列會顯示「排隊辨識中 / 辨識中… / 待覆核」三種狀態,辨識完成後畫面自動更新。
> 拍完就可以離開現場 —— 辨識在伺服器端繼續進行,不需要保持頁面開著。

> **拍攝前請先看畫面上方的引擎狀態列。**
> 出現紅色「⚠ 目前為模擬引擎」時,拍照後拿到的是固定樣張假資料(陳○宏),不是你拍的內容 ——
> 這是開發用的預設設定。請先請系統管理者切換為真實引擎
> (見 [AI服務使用說明.md](AI服務使用說明.md)),否則整批照片都要重跑辨識。

> 首次使用請在**連上區網時**先開啟過系統一次(完成離線快取),此步驟應納入出勤前裝置整備 SOP。

### 2.2 覆核 AI 辨識結果(選單「覆核佇列」)

1. 佇列依上傳時間排序,點任一筆進入覆核畫面。標示「AI 降級・人工輸入」者為全空白表單。
2. 覆核畫面左側為原始影像(點擊可開新視窗放大),右側為依紀錄單區塊排列的欄位:
   - 每個欄位旁有 AI 信心分數徽章:綠色(高信心)、灰色(中等)、**黃色=信心不足**。
   - **黃色底框的欄位請務必對照影像確認**,必填欄位(檢傷分類、性別、傷票編號)與身分證字號採更嚴格門檻。
3. 畫面上方紅色警示列為自動檢核結果(如「SBP 低於 90,請確認休克風險」「必填欄位缺漏」),請逐項確認。
4. 需要重跑辨識時,按右上角「**↻ 重新辨識**」:
   - 以**目前**的 AI 引擎對同一張影像重跑,不需重新拍照。
   - 適用時機:AI 服務先前沒啟動、剛從模擬引擎切換為真實引擎、或調整過信心門檻。
   - 舊辨識結果會被覆寫;已完成覆核(寫入傷患主檔)的影像不再重跑。
5. 修正完成後點「**確認無誤,寫入傷患資料**」:
   > 在欄位裡按 **Enter 不會送出表單**。覆核送出會寫入傷患主檔且不可逆,
   > 因此一定要明確點擊按鈕。現病史欄的 Enter 仍是換行,可正常打多行。
   - 資料寫入傷患主檔並新增一筆檢傷紀錄,儀表板即時更新。
   - 若傷票編號已存在,系統視為**同一傷患的複檢或補頁**,自動併入並保留檢傷歷程(畫面會提示)。
   - AI 原始結果與人工修正差異會完整保留,供事後品質分析。

### 2.3 刪除單張待覆核影像(限站長/系統管理者)

覆核佇列每一列右側有**刪除**按鈕,一次只刪一張,佇列中其他影像不受影響。
會一併刪除該影像的 AI 辨識結果與磁碟上的照片檔。

主要用途:清掉拍壞的、重複的、或測試用的影像,避免佇列被雜訊塞滿。

> **已完成覆核的影像刪不掉。** 那些影像已成為某位傷患病歷的原始憑證,
> 從佇列端單獨刪除會讓傷患資料失去出處卻無跡可循。系統會擋下並提示 ——
> 若確定要移除,只能從儀表板刪除整位傷患(見 2.4)。

第一線醫護沒有這個按鈕:拍歪拍糊重拍一張即可,不必刪;
而誤刪別人剛上傳、還沒覆核的紀錄單會直接損失現場資料。

### 2.4 刪除傷患資料(限系統管理者)

儀表板「最近傷患」每一列右側有**刪除**按鈕,僅 `admin` 角色看得到。
主要用途是清理演練資料。

會一併永久刪除:

- 傷患主檔與過去病史
- 所有檢傷紀錄與初步診斷
- 該傷患的原始紀錄單影像,**包含磁碟上的照片檔**

不會刪除:

- **稽核紀錄**。刪除行為本身會寫入 AuditLog,而 AuditLog 僅可新增與查詢
  (架構書 8.4)—— 資料可以刪,但「誰在何時刪了哪一位傷患」的軌跡會留存。
- **尚未覆核的影像**。那些影像還沒綁定傷患,不屬於任何一位傷患的資料。

> ⚠ 此操作**無法復原**,按下後會跳出確認視窗。
> 由於影像的 SHA-256 去重索引也一併移除,刪除後同一張照片可以重新上傳 ——
> 這在反覆測試辨識效果時很有用。

### 2.5 查詢傷患(選單「傷患清單」)

- **搜尋**:輸入傷票編號或姓名的一部分即可(如 `SIM`、`陳`),不分大小寫。
- **篩選**:可依檢傷分類與動向組合篩選,例如「黃標 + 待後送」= 接下來要上車的人。
- 清單依**檢傷分類**排序(紅→黃→綠→黑→緩),同級再依最近更新 —— 最需要處理的排在最前面。
- 每頁 50 筆,標題右側顯示符合條件的總人數。

> 舊版是「最近更新的 200 筆」,超過之後最早進站的傷患會從畫面消失 ——
> 而那些往往正是還在等後送的人。現已改為條件查詢加分頁,不會再有看不到的傷患。

明細頁包含:基本資料(身分證字號一律遮罩顯示)、過去病史、初步診斷、
**檢傷紀錄歷程**(每次複檢一列)、原始紀錄單影像。

### 2.6 更新動向(收治中/待後送/後送中/離站/死亡)

傷患明細頁最上方是一排動向按鈕,點一下即生效,目前狀態以實心按鈕標示。
儀表板與戰情看板的「返家 / 後送 / 死亡 / 處置中」即時跟著變動。

> **標記「死亡」會跳出確認**,並自動把檢傷分類改為黑標、補一筆檢傷紀錄。
> 兩者代表同一件事,分開記錄會讓看板出現「死亡 3 人、黑標 1 人」這種互相矛盾的數字。
> 其餘動向切換不需確認 —— 後送、離站本來就會來回變動,每次都確認只會養成不看就按的習慣。

權限:醫護人員、站長、系統管理者。**指揮官沒有這排按鈕** —— 指揮官看的是全站態勢、
不在床邊,由他改個別傷患的動向會與現場實況脫節。

### 2.7 現場重新檢傷(不必重拍紙本)

明細頁「**↻ 重新檢傷**」可直接新增一筆檢傷紀錄並更新目前分類。
生命徵象會預填上一筆的值,只需改動有變化的欄位。

適用時機:病情在站內惡化或好轉。舊紀錄一律保留 —— 事後檢討要看的是病情的變化軌跡,
不只是最後狀態。選擇黑標時動向會同步改為死亡。

### 2.8 修正已覆核的資料

明細頁「**✎ 修正基本資料**」可修改傷票編號、姓名、性別、年齡、生日、國籍、
身分證字號與現病史,不必刪掉整位傷患重來。所有修改都會寫入稽核紀錄(改了哪些欄位、
從什麼變成什麼)。

- **傷票編號可以改,但不可與他人重複** —— 編號是多頁紀錄單併檔的依據(附錄 B.3),
  重複會把兩位傷患的資料合在一起。系統會擋下並提示。
- **身分證字號留空代表「不變更」**,不是清空。該欄加密儲存、畫面只看得到遮罩,
  若把空白當成刪除,只要有人沒填就會把既有資料洗掉。要清空請填入單一個 `-`。

## 3. 指揮官操作(選單「儀表板」)

- 統計卡:傷患總數、紅/黃/綠/黑/緩和治療五類分佈、收治中、待後送、待覆核影像數。
- 右上角「連線狀態」:
  - **即時連線**(綠):SignalR 推播中,資料異動 1~2 秒內自動更新。
  - **輪詢備援**(黃):推播斷線,自動改為每 10 秒查詢一次,恢復後自動切回並重新拉取完整快照,期間異動不會遺失。
- 「最近傷患」表點列可進入傷患明細。

## 4. 資料與維運

| 項目 | 說明 |
|---|---|
| 資料位置 | `src\Dmat.Web\app_data\`:`dmat.db`(SQLite)、`images\`(紀錄單影像)、`keys\`(加密金鑰) |
| 備份 | 直接複製整個 `app_data` 資料夾(建議停機或閒置時複製) |
| 清空重來 | 停止服務後刪除 `app_data` 資料夾,重新啟動會自動重建資料庫與種子帳號 |
| 日誌 | `src\Dmat.Web\logs\dmat-yyyyMMdd.log`(Serilog 逐日滾動) |
| 稽核 | 登入、上傳、覆核確認均寫入 AuditLog,僅可新增與查詢,不可修改刪除 |

## 5. 疑難排解

| 症狀 | 處理 |
|---|---|
| 頁面打不開 | 確認 `dotnet run` 仍在執行、防火牆放行 5100 埠;手機需與主機同一區網 |
| 登入被鎖定 | 等 15 分鐘,或改用其他帳號 |
| 上傳後一直「待傳」 | 檢查裝置是否連上區網;連上後留在頁面等待自動補傳 |
| 手機上傳很慢、要重新整理才會傳下一張 | **已修正**。舊版的上傳請求會等整個 OCR 跑完(數十秒到數分鐘)才回應,期間佇列被鎖住。現在上傳只做存檔與排隊,辨識改在伺服器背景處理 |
| 全部變成人工輸入 | AI 服務未啟動或無回應,見《AI服務使用說明.md》檢查 8100 埠 |
| **覆核畫面永遠是「陳○宏」** | AI 服務跑在**模擬引擎**,結果是固定樣張假資料。請管理者依《AI服務使用說明.md》執行 `scripts/setup-ocr.sh` 切換真實引擎,再按「↻ 重新辨識」 |
| **重拍同一張還是舊結果** | SHA-256 去重會回傳既有紀錄。用覆核頁的「↻ 重新辨識」強制重跑 |
| 覆核佇列被測試影像塞滿 | 以站長或 admin 登入,逐張按「刪除」;已覆核的影像會被擋下,那要從儀表板刪整位傷患 |
| 想重新上傳同一張照片測試 | 先刪掉舊的那張(SHA-256 去重索引會一併釋出),即可重新上傳 |
| 空白欄位被填入「4.生命徵象」之類的表格標題 | **已修正**。某欄空白時,擷取邏輯會往下一格/下一行找值,而國籍正好緊接著下一區的標題。現在區塊標題一律不當成值,空白就留空 |
| 體溫讀不到(其他生命徵象都正常) | **已修正**。「36.7**度**C」的中文單位曾被誤判為下一個欄位的開頭,整個值被截掉 |
| 辨識到的欄位很少 | 拍攝時整頁入鏡、放平、避免反光;直立拍攝優於橫拍。仍不佳請管理者用 `tools/try_image.py --raw` 檢查 OCR 是否真的讀到文字 |
| 點紀錄單影像出現錯誤 / 顯示破圖 | 若傷患明細顯示「⚠ 影像檔遺失」,表示資料庫有紀錄但磁碟上找不到檔案,請確認 `app_data/images` 是否完整。**注意:資料庫在 Windows 與 Linux 之間搬移過的舊紀錄曾因路徑分隔符不同而失效,此問題已修正,不需要手動處理資料。** |
| 儀表板顯示「輪詢備援」 | 屬正常備援行為;若持續,重新整理頁面即可重建連線 |
